動画生成ガイド

台本（script.json）から、音声・字幕・図解アニメーション付きの解説スライド動画（MP4）を作る手順書です。

目次

全体像

やることは「台本を用意する → 音声を作る → 動画に書き出す」の3ステップです。台本を差し替えるだけで、音声の長さに合わせて字幕と図の表示タイミングが自動で決まります。

作り方は3通り

方法向いている人必要なもの
ローカルで作る台本を手元で編集・プレビューしたいNode.js 18以上、VOICEVOX Engine
LLMで台本も作る題材やURLから下書きを作りたい上記 + OPENAI_API_KEY
GitHub Actionsで作る手元に環境を作りたくないGitHubリポジトリのみ

準備する

  1. 依存パッケージを入れる

    Node.js 18以上を用意し、リポジトリのルートで実行します。フォント（Noto Sans JP）は同梱済みで、レンダリング時に外部通信は不要です。

    npm install

  2. VOICEVOX Engineを起動する

    音声生成（npm run audio）の前に、http://localhost:50021 でエンジンを動かします。

    Dockerの場合

    docker run -d --rm --name voicevox -p 127.0.0.1:50021:50021 voicevox/voicevox_engine:cpu-latest

    デスクトップアプリの場合：VOICEVOXを起動し、設定で「APIサーバー」を有効にします。

    Windowsの注意 -p の値を引用符で囲まないでください。cmd.exeでは引用符が値の一部になり、invalid IP address エラーになります。Docker Desktopが起動していることも確認してください。

  3. 起動を確認する

    curl http://localhost:50021/version

    バージョンが表示されれば準備完了です。

    エンジンなしで試す npm run audio:mock なら無音WAVと概算の長さでタイムラインを作れます。レイアウトやタイミングの確認に便利です。

ローカルで作る

  1. 音声とタイムラインを作る

    npm run audio

    public/script.json の各セリフを音声にして public/audio/ に保存し、各セリフの開始フレームを public/timeline.json に書き出します。

  2. プレビューで確認する

    npm run dev

    Remotion Studio（http://localhost:3000）が開きます。音声・字幕・図の出現タイミングを再生して確認します。

  3. MP4に書き出す

    npm run render

    out/video.mp4 が出力されます。動作が重いときは npm run render -- --concurrency=4 のように同時実行数を指定します。

台本を直したら必ず音声を作り直す script.json を編集したら、プレビューや書き出しの前に npm run audio を再実行します。しないと timeline.json が古いままになり、Remotionがエラーを出します。

コマンド早見表

コマンド役割

台本を書く

台本は public/script.json です。1シーンが1枚のスライドで、シーンの中に複数のセリフを並べます。

{
  "scenes": [
    {
      "id": "flow",              // シーンID（音声ファイル名に使う）
      "layout": "flow",          // レイアウト種別（下表）
      "label": "FLOW",           // 左上の英字ラベル（省略可）
      "heading": "処理の流れ",    // 見出し（titleでは省略）
      "content": { ... },        // レイアウトごとの中身
      "lines": [
        {
          "text": "ナレーション文（読み上げと字幕に使われる）",
          "reveal": ["step-1"]   // このセリフの開始時に出す要素のID
        }
      ]
    }
  ]
}

reveal の考え方

  • reveal に書いた要素は、そのセリフが始まる瞬間にフェードインします。
  • reveal に書かれない要素は、シーン開始から常に表示されます。
  • シーンには chapter（左下の章タグ）と badge（右上のバッジ）も付けられます。

レイアウト一覧

layout用途と content の中身reveal に使えるID
titleタイトル画面。kicker? / title / subtitle?なし（常時表示）
section章扉。number? / title / subtitle?なし（常時表示）
compare左右比較。leftTitle / rightTitle / left[] / right[]（各項目 { id, icon?, title, body?, tone? }）各項目の id
flow手順の流れ。steps[]（2つ以上）各stepの id、矢印 arrow-1〜
inputOutput入力→変換→出力。input / transform / output各 id、矢印 arrow-1, arrow-2
bullets縦の箇条書き。items[]各項目の id
stats数字を強調するカード（2〜4枚）。items[] は { id, value, label, body? }各項目の id
table比較表。headers[] + rows[] + source?各行の id
bars横棒グラフ。items[] + caption?各項目の id、caption
checklist番号付きチェックカード。items[] は { id, text, note? }各項目の id
axes空の座標軸の図解。xAxis / yAxis / hint?axes、hint

アイコンと素材集

  • icon には約45種のキー（check、search、shield-check など）が使えます。一覧は src/components/IconBox.tsx の REGISTRY にあり、追加もそこに書くだけです。
  • 書き方の見本は public/script.json（約9分・全レイアウト網羅）と templates/sample-claude-code-7scenes.json（7シーン版）。シーン単位でコピーして使えます。

長さの目安

10分の動画はナレーション約3,000字、25〜30シーン・80〜90セリフが目安です。長い動画は section（章扉）と chapter タグで章立てすると見やすくなります。10分を超えると npm run audio が警告を出します（止まりはしません）。

台本を自動生成する

OpenAI互換のChat Completions APIで、プロンプトまたは記事URLから台本を作れます。生成結果は public/script.json を上書きします。

export OPENAI_API_KEY="sk-..."

# プロンプトから
npm run script -- "Remotionの魅力を解説する動画の台本を作って"

# 記事URLから
npm run script -- --url https://example.com/article

# 続けて音声 → 書き出し
npm run audio && npm run render
環境変数既定値説明
OPENAI_API_KEY（必須）APIキー
OPENAI_BASE_URLhttps://api.openai.com/v1互換エンドポイント（Ollamaなら http://localhost:11434/v1）
SCRIPT_MODELgpt-4o-miniモデル名（JSON mode対応を推奨）
  • スキーマ検証に失敗すると、エラー内容を渡して1回だけ自動リトライします。
  • URL指定は本文テキストを抽出します。JavaScriptで描画されるページやログイン必須のページは取得できません。その場合は本文をコピーしてプロンプトとして渡してください。
  • 生成後は内容を確認・手直ししてから npm run audio を実行してください。

GitHub Actionsで作る

手元に環境を作らずに、GitHub上で音声生成からレンダリングまで実行できます。ワークフローは .github/workflows/generate-video.yml です。

起動方法

  1. 手動で実行する

    GitHubの Actions タブ → generate-video → Run workflow を開き、source_type を選びます。

    source_type動作
    noneリポジトリの public/script.json をそのまま動画化
    prompt入力したプロンプトからLLMで台本を作って動画化
    url入力したURLの記事から台本を作って動画化

    prompt / url を使うには、リポジトリの Settings → Secrets and variables → Actions に OPENAI_API_KEY を登録します。任意で Variables に OPENAI_BASE_URL / SCRIPT_MODEL も設定できます。

  2. APIから実行する

    repository_dispatch で外部から起動できます（repo権限のPATが必要）。

    curl -X POST \
  -H "Authorization: Bearer <YOUR_PAT>" \
  -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/<user>/<repo>/dispatches \
  -d '{"event_type":"generate-video","client_payload":{"source_type":"url","source":"https://example.com/article"}}'

  3. 完成した動画を受け取る

    実行が終わったら、そのRunのページ下部の Artifacts から video（video.mp4）をダウンロードします。保存期間は30日です。台本を自動生成した場合は、script.json と timeline.json もリポジトリにコミットされます。

ワークフローの流れ

  1. VOICEVOX Engineをサービスコンテナで起動し、応答するまで待つ
  2. npm ci と Remotion用ブラウザの準備
  3. （prompt / url のとき）台本を生成
  4. npm run audio → npm run render
  5. out/video.mp4 をアーティファクトに保存
費用の目安 公開リポジトリなら無料です。プライベートは無料枠が月2,000分で、10分の動画1本につき実行時間は約20〜40分を見込みます。

困ったとき

症状原因と対処
「VOICEVOX Engine に接続できません」エンジンが未起動です。準備のコマンドで起動するか、npm run audio:mock を使います。
docker: invalid IP address-p の値を引用符で囲んでいます。引用符なしで実行してください。
「timeline.json に … 対応するエントリがありません」台本を直した後に npm run audio を実行していません。再実行します。
音声と表示がずれるnpm run audio をやり直します。タイムラインは音声の実寸から再計算されます。
レンダリングが遅い・落ちるnpm run render -- --concurrency=4 のように同時実行数を下げます。
Actionsで「OPENAI_API_KEY が未設定」Secretsに登録するか、source_type=none で既存の台本を使います。
